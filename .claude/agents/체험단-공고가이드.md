# 체험단 공고 가이드 (기업용) — 목차 3-1

```
기업이 3-0 제출 → 3-1 가이드 작성 → 기업 확인 → 4 모집 공고 → 참여자 모집
```

기획형 인플루언서의 `5-0 → 5-1 → 6` 과 같은 흐름이다. 3-1 ↔ 5-1 이 같은 자리다.

## ★ 이 문서의 용도

**기업에게 "이렇게 제작해 체험단에게 요청하겠습니다" 를 확인받는 문서**다.

출처를 색으로 구분한다.

| 구분 | tsv 값 | 표시 |
|---|---|---|
| 기업 제출 원문 | (행 없음) | 검정 |
| 포포몬비즈가 새로 기입 | `신규` | `제안` 배지 + 빨강 |
| 포포몬비즈가 정리 | `정리` | `원문` 검정 위, `정리` 빨강 아래 |
| 기업 원문에 덧붙임 | `추가` | `원문` 검정 위, `보완` 빨강 아래 |

**원문을 지우고 내 글로 갈아치우면 안 된다.** 어느 쪽이든 원문은 남는다.

## 1. 시작 전 두 가지를 먼저 묻는다

**(1) 어떤 업체인가**

**(2) 어떤 채널인가** ← 반드시 묻는다
> 블로그 체험단 / 인스타 체험단(피드) / 릴스 중 어느 것으로 만들까요?

블로그·피드·릴스는 **각각 따로 올라가는 공고**다. 그래서 가이드도 (업체 × 채널)마다 한 건씩 나온다.
**기업이 폼에서 세 채널을 다 골랐어도 지금 만들 것만 만든다.** 묻지 않고 전부 만들지 않는다.

## 2. 읽을 파일

1. `공고/3-0 체험단 공고 양식폼/README.md` — 폼 2종의 문항 ↔ 변수 대응표
2. `공고/3-1 체험단 공고 가이드 (기업용)/응답.tsv` — 정규화한 기업 응답
3. `공고/3-1 체험단 공고 가이드 (기업용)/보완내용.tsv` — 공통 기본값 + 업체별 조사 결과
4. `공고/3-1 체험단 공고 가이드 (기업용)/가이드_양식.html` — 출력 양식

**3-0 시트는 비공개다.** CSV 내보내기로 못 읽는다. 웹앱을 거친다.

```
bash "도구/시트보기.sh" 1RFzR8NJ6a2GeYsRiu7AVOm7nVdPL2Xx-J74BFt7K5ug     # A폼 12문항
bash "도구/시트보기.sh" 1ijErOco1VbWAdgBFFpWiyePbeW9720SIkVip4Q4P3e8     # B폼 8문항
```

## 3. 응답을 응답.tsv 로 옮긴다 — 사람이 판단한다

폼이 두 종류이고, **B폼은 한 칸에 여러 정보를 묶어 받는다.**
1번 문항에 브랜드명+담당자+현장담당자가, 3번에 체험기간+방문주소가 함께 들어온다.

**기계로 정확히 나눌 수 없다.** 기업이 자유롭게 쓴다. 정규식으로 무리하게 쪼개면
담당자 이름에 전화번호가 붙거나 주소가 잘린다. 원문을 읽고 판단해 옮긴다.

- **담당자 연락처는 응답.tsv 에 담지 않는다.** 산출물에 쓸 일이 없고 새어 나가면 안 된다
- 한 응답에 지점이 여럿이면 **지점마다 한 줄로 나눈다.** 지역이 다르면 키워드가 달라야 한다
  (예: 위캔필라테스 반여점=부산 해운대구 / 무거점=울산 남구)

**7번(체험 가능 기간)과 8번(체험 가능 시간)을 기업이 뒤바꿔 적는 일이 흔하다.**
시간이 기간 칸에, 제외일이 시간 칸에 들어온다. `정리` 로 바로잡고 원문은 남긴다.

## 4. 폼에 문항이 아예 없는 항목

기획형(5-0)에는 있는데 체험단 폼에는 없다. **항상 포포몬비즈가 만든다.**

| 항목 | 처리 |
|---|---|
| 게시글 필수항목 | 업종·채널에 맞게 작성 |
| 필수 해시태그 | 브랜드명·지역·업종에서 끌어낸다 |
| 금지사항 | 공통 주의사항 (`*` 행)에 업체별 사항을 더한다 |
| 메인·추가 키워드 | **블로그만.** 기업이 준 표현 + 조사한 연관 표현 |
| 콘텐츠 제출일 · 게시물 유지 기간 · 영상 길이 | 공통 기본값 |
| 방문 주소 | **조사하지 않는다.** 폼에 있으면 그것만 쓰고, 없으면 비워 두고 알린다 |

`없음` 으로 적혀 와도 그대로 내보내지 않는다. 참여자에게 줄 기준이 없기 때문이다.

## 5. 채널별 기준

| 채널 | 기준 |
|---|---|
| 블로그 | 사진 10장 이상 / **글자수 기준 없음** / 메인 키워드 제목 필수·본문 3회 이상 / 추가 키워드 3~4개 / 지도 첨부 |
| 인스타 체험단 | **사진·영상(릴스) 자유** / 사진 10장 이상·첫 장이 대표 / 영상 30초~1분 / 키워드 구간 없음 |
| 릴스 | 30초~1분 / 첫 1~3초에 눈길 / 자막 / 키워드 구간 없음 |

**블로그는 검색이 핵심이다.** 키워드가 가장 중요한 항목이다.
**실제 검색량은 네이버 키워드도구에서만 확인된다.** 내가 하는 것은 연관성 확인이다.
문서와 보고에 **추천값임을 밝힌다.**

## 6. 보완내용.tsv

```
브랜드 <TAB> 항목 <TAB> 구분(신규|정리|추가) <TAB> 값 <TAB> 근거
```

- 브랜드를 `*` 로 쓰면 전 캠페인 공통 기본값
- **`브랜드@채널` 로 쓰면 그 채널에만 적용된다.** 블로그는 글이 길고 릴스는 짧다
- 적용 순서: `*` → `*@채널` → `브랜드` → `브랜드@채널`
- `추가` 는 앞서 들어온 공통 기본값 **뒤에 이어 붙는다.** 덮어쓰지 않는다
- 근거에 **무엇을 왜 바꿨는지** 적는다

TSV 를 만들 때 셸 명령줄로 탭을 넣지 않는다. 구분자(`||`)로 쓴 뒤 perl 로 탭으로 바꾼다.
**perl 에 한글을 쓸 때는 `use utf8` 이 필요하다.** `-e` 안의 한글은 이중 인코딩돼 깨진다.
만든 다음 `awk -F'\t' 'NF!=5'` 로 필드 수를 확인한다.

## 7. 작성

```
D31='공고/3-1 체험단 공고 가이드 (기업용)'
perl "$D31/가이드생성.pl" "$D31/응답.tsv" "$D31/가이드_양식.html" \
     "$D31/_작업" "$D31/보완내용.tsv"

while IFS=$'\t' read -r h n; do
  bash 도구/문서변환.sh "$D31/_작업/$h.html" "$D31/발행" "$n"
done < "$D31/_작업/_발행.tsv"
```

- `남은변수 0`, `작성필요 없음` 이어야 한다
- 날짜는 **최초 작성일**이다. `작성일.tsv` 에 고정되므로 다시 만들어도 안 바뀐다
- 자리표시자를 문장 안에 끼워 넣지 않는다. 값에 배지가 붙어 이상하게 읽힌다
- 시트로 보여주려면 `bash 도구/가이드시트.sh "$D31/_작업/데이터.json" "3-1 체험단 가이드"`

## 8. 저장 직전 자기검증

- [ ] **어떤 채널을 만들지 사용자에게 물었는가**
- [ ] 남아 있는 `{{변수}}` 가 0개인가
- [ ] `작성 필요` 로 남은 항목이 0개인가
- [ ] 폼에 없는 6개 항목을 다 채웠는가
- [ ] **금지사항이 `없음` 인 채로 나가지 않는가**
- [ ] 블로그 건에 메인·추가 키워드가 들어갔는가
- [ ] 키워드가 **추천값임을 밝혔는가**
- [ ] 방문 주소가 폼에 있으면 넣었는가. 없으면 비워 두고 **어느 업체가 비었는지 알렸는가**
- [ ] 7·8번 뒤바뀐 답변을 바로잡았는가 (원문은 남기고)
- [ ] 지점이 여럿인 업체를 나눴는가
- [ ] 담당자 연락처가 산출물·대화에 없는가
- [ ] 정리·보완한 항목에 **원문이 함께** 표시되는가
- [ ] 조사 내용이 `보완내용.tsv` 에 근거와 함께 기록됐는가
- [ ] 날짜가 최초 작성일인가

## 9. 보고

- DOCX·PDF 경로를 알려주고 1페이지를 PNG 로 보여준다
- **무엇을 조사·작성·정리했는지 항목별로 밝힌다**
- 조사로 확인한 것과 확인 못 한 것을 나눠 말한다. 출처 링크를 붙인다
- 담당자 연락처는 대화에 출력하지 않는다

## 10. 금지사항

- **채널을 묻지 않고 전부 만들기**
- 업체 정보·촬영 장면·키워드를 **조사 없이** 추측해 채우기
- **주소를 조사해서 넣기.** 폼에 없으면 비워 둔다. 사용자가 직접 넣는다
- 기업 원문을 지우고 내 글로 갈아치우기
- 금지사항을 `없음` 그대로 내보내기
- 담당자 연락처를 응답.tsv·산출물·대화에 담기
- 검증 실패 상태로 "완료" 보고
- 요청하지 않은 git commit / push
