# 진행업체 체험단 공고 가이드 (모집용) — 목차 4

```
기업이 3-0 제출 → 3-1 가이드 작성 → 기업 확인 → 4 모집 공고 → 참여자 모집
```

기획형 인플루언서의 6번과 같은 자리다. 3-1 ↔ 5-1, 4 ↔ 6 이 짝이다.

## ★ 이 문서의 용도

**참여자가 보고 지원하는 모집 공고**다. 3-1 과 독자가 다르다.

| | 3-1 공고 가이드 | 4 모집 공고 |
|---|---|---|
| 보는 사람 | 기업 담당자 | 체험단 참여자 |
| 목적 | 이렇게 요청하겠다는 확인 | 지원 모집 |
| 색 구분 | 검정/빨강 | 없음 (확정본만) |
| 표 | 사용 | **사용 안 함** |
| 출력 | DOCX·PDF | 업로드용 텍스트 + 미리보기 PDF |

**표를 쓰지 않는다.** 공고 업로드 화면에서 표를 못 쓴다.
제목 · 문단 · 불릿 · 번호 목록만 쓴다.

## 1. 시작 전 세 가지를 먼저 묻는다

**(1) 어떤 업체인가**

**(2) 어떤 채널인가** ← 반드시 묻는다
> 블로그 체험단 / 인스타 체험단(피드) / 릴스 중 어느 것으로 만들까요?

채널마다 따로 올라가는 공고다. 묻지 않고 전부 만들지 않는다.

**(3) 3-1 이 기업 확인을 받았는가**
승인 전 내용으로 공고를 올리면 참여자에게 잘못된 조건이 나간다. 되돌릴 수 없다.

## 2. 실제 운영 공고 양식을 따른다

포포몬에 올라간 공고를 그대로 본떴다. 순서를 바꾸지 않는다.

```
이렇게 홍보해 주세요!        → 모집 소개
<체험단 제공 안내>            제공 상품 / 금액 / 인원 + ※ 양도 불가
<방문 및 체험 안내>           장소 / 주소 / 시간 / 일정 / 업로드 + 번호 안내
  (배송형은 <체험 진행 안내> 로 바뀐다)
매장 인스타그램 등 링크
<콘텐츠 작성 안내>
<꼭 소개해 주세요>
<제목 및 키워드 작성 안내>    ← 블로그만
<추가키워드>                  ← 블로그만
<사진 촬영 안내>
<필수 해시태그>
유의사항                      포포몬 공통 5줄. 문구를 바꾸지 않는다
```

**포포몬 체험단임을 밝히는 안내를 번호 목록으로 넣는다.**
「포포몬 체험단으로 방문했습니다」라고 말하기, 아이디·선정 화면 보여주기,
다른 손님 얼굴 촬영 주의 등. 방문형에 반드시 들어간다.

## 3. 내용은 3-1 확정본에서 가져온다

**따로 입력받지 않는다.** `공고/3-1 .../_작업/데이터.json` 을 읽는다.
3-1 이 기업 확인을 받은 내용이다. 여기서 따로 쓰면 승인받은 것과 갈라진다.

확정본 규칙 (3-1 의 구분별):

| 3-1 구분 | 4 에서 쓰는 값 |
|---|---|
| 원문 | 기업 원문 그대로 |
| 제안 | 포포몬비즈가 새로 쓴 것 |
| 정리 | 정리본만 (원문은 버린다) |
| 보완 | 원문 + 보완 (둘 다 필요하다) |

3-1 내용을 고쳐야 하면 **여기서 고치지 않는다.** `보완내용.tsv` 를 고치고 3-1 을 다시
발행한 뒤 4 를 다시 만든다.

공고에만 필요한 것(모집 소개 문구, 제공 금액·인원, 방문 안내 번호 목록, 키워드,
브랜드 링크)은 `공고내용.tsv` 에 쓴다.

```
브랜드 <TAB> 항목 <TAB> 값
```
`브랜드@채널` 로 쓰면 그 채널에만 적용된다. 적용 순서는 `브랜드@채널` → `브랜드` → `*@채널` → `*`.

## 4. 빈말은 항목째로 지운다

`없음`, `없음.`, `아직 미정`, `별도 전달`, `별도 협의`, `추후 안내` 는 읽는 사람에게
아무 정보가 없다. 생성기가 그 줄·문단을 통째로 지운다.

- 3-1(기업 확인용)에는 원문이 그대로 남는다. 4 에서만 빠진다
- 한 줄 항목(`- 방문 가능 시간: …`)에 들어가는 값은 줄바꿈을 ` / ` 로 바꾼다.
  그대로 두면 둘째 줄이 불릿 밖으로 튀어나가 목록이 끊긴다

## 5. 채널별 차이

| 채널 | 작성 안내 | 키워드 구간 |
|---|---|---|
| 블로그 | 게시물 1건, 직접 촬영 사진 10장 이상 | **있음** (메인 + 추가) |
| 피드 | 사진 10장 이상, 첫 장이 대표 | 없음 |
| 릴스 | 30초~1분, 첫 1~3초, 자막 | 없음 |

**블로그는 검색이 핵심이다.** 메인 키워드를 제목에 넣고 본문 3회 이상,
추가 키워드는 3~4개 이상 쓰게 한다.
**검색량은 네이버 키워드도구에서만 확인된다.** 추천값임을 보고에 밝힌다.

## 6. 작성

```
D31='공고/3-1 체험단 공고 가이드 (기업용)'
D4='공고/4 진행업체 체험단 공고 가이드 (모집용)'
perl "$D4/공고생성.pl" "$D31/_작업/데이터.json" "$D4/공고_양식.txt" \
     "$D4/_작업" "$D4/공고내용.tsv"

bash 도구/글미리보기.sh "$D4/_작업/_목록.txt" "$D4/미리보기" 목록
```

- `_작업/` 의 `.txt` 가 **실제 업로드용**이다. 이 내용을 공고 화면에 붙인다
- `미리보기/` 의 PDF·PNG 는 **검토용**이다
- 날짜는 3-1 에서 넘어온 **최초 작성일**이다. 다시 만들어도 안 바뀐다
- `남은변수 0`, `확인필요 0` 이어야 한다

## 7. 저장 직전 자기검증

- [ ] **어떤 채널을 만들지 사용자에게 물었는가**
- [ ] **3-1 이 기업 확인을 받았는가**
- [ ] 남아 있는 `{{변수}}` 가 0개인가
- [ ] `❗확인 필요` 가 0개인가
- [ ] **표가 하나도 없는가**
- [ ] 유의사항 5줄이 그대로 있는가
- [ ] 포포몬 체험단임을 밝히는 안내가 들어갔는가 (방문형)
- [ ] 방문 주소가 폼에 있으면 들어갔는가. 없으면 알렸는가
- [ ] 블로그 건에 메인·추가 키워드가 들어갔는가
- [ ] 한 줄 항목에 줄바꿈이 남아 목록이 끊기지 않는가
- [ ] `없음`·`아직 미정`·`별도 전달` 이 남아 있지 않은가
- [ ] 사람태그가 **이 업체(지점)의** 계정인가
- [ ] 날짜가 최초 작성일인가

## 8. 보고

- 업로드용 텍스트 경로와 미리보기 PDF 경로를 함께 알려준다
- **업로드는 `_작업/` 의 텍스트를 쓴다는 점을 밝힌다.** PDF 는 검토용이다
- 무엇을 새로 썼는지 밝힌다 (모집 소개, 키워드, 방문 안내)
- 확인 못 한 항목이 있으면 그것도 밝힌다

## 9. 금지사항

- **채널을 묻지 않고 전부 만들기**
- **3-1 기업 확인 전에 공고 만들기**
- 3-1 을 거치지 않고 내용을 직접 써넣기 (`공고내용.tsv` 외)
- 표 사용
- 유의사항 5줄 문구 변경
- 빈말(`별도 전달` 등)을 그대로 내보내기
- 주소를 조사해서 넣기
- 날짜를 오늘 날짜로 다시 붙이기
- 검증 실패 상태로 "완료" 보고
- 요청하지 않은 git commit / push
