# 기획형 인플루언서 공고 가이드 작성 에이전트 (목차 5-1)

```
광고주가 5-0 폼 제출 → 응답 시트 → 5-1 가이드 작성 → 광고주 확인 → 인플루언서 전달
```

## ★ 이 문서의 용도

**광고주에게 "이렇게 제작해 인플루언서에게 요청하겠습니다" 를 확인받는 문서**다.
승인 뒤에는 **그대로 인플루언서에게 전달된다.** 그래서 두 가지를 동시에 만족해야 한다.

1. 광고주가 무엇이 바뀌었는지 한눈에 보고 수정 요청할 수 있어야 한다 → **색으로 출처 구분**
2. 인플루언서가 읽고 바로 촬영할 수 있어야 한다 → **쉬운 말, 제안하는 어조**

**출처는 색으로 구분한다.**

| 구분 | tsv 값 | 표시 |
|---|---|---|
| 광고주 제출 원문 | (행 없음) | 검정 |
| 포포몬비즈가 새로 기입 | `신규` | `제안` 배지 + 빨강 |
| 포포몬비즈가 정리(축약·수정) | `정리` | `원문` 검정 **위**, `정리` 빨강 **아래** |
| 광고주 원문에 덧붙임 | `추가` | `원문` 검정 **위**, `보완` 빨강 **아래** |

`정리` 와 `추가` 의 차이:
- **정리** — 원문이 너무 길거나 복잡하거나 대화체 잔문이 섞여 있다. 같은 내용을 다시 쓴다
- **추가** — 원문은 맞지만 너무 짧아 인플루언서가 이걸로 촬영할 수 없다. 원문은 그대로 두고 밑에 보탠다

**원문을 지우고 내 글로 갈아치우면 안 된다.** 어느 쪽이든 원문은 남는다.

## 0. 시작 전 반드시 읽을 파일

1. `공고/5-1 기획형 인플루언서 공고 가이드/가이드_양식.html` — 출력 양식
2. `공고/5-1 기획형 인플루언서 공고 가이드/보완내용.tsv` — 공통 기본값 + 브랜드별 조사 결과
3. `공고/5-0 new 기획형 인플루언서 양식폼(응답)/README.md` — 19문항 ↔ 변수 대응표
4. `공고/5-0 new 기획형 인플루언서 양식폼(응답)/응답/응답시트_19문항.csv` — 광고주 응답
5. `공고/5-1 기획형 인플루언서 공고 가이드/발행/` — 기존 발행 이력

## 1. 첫 응답 — 두 가지를 먼저 묻는다

내용을 만들기 전에 **반드시** 확인한다.

**(1) 어떤 광고주(브랜드) 건인가**
- 응답 시트의 브랜드 목록을 보여주고 고르게 한다
- 최신 응답이 필요하면 먼저 받아온다
  ```
  bash "도구/시트받기.sh" "1QDKvfEF31SDT0vN8rkwyLtcb7c6sJikLtXWICqrpUEY" \
       "공고/5-0 new 기획형 인플루언서 양식폼(응답)/응답/응답시트_19문항.csv"
  ```

**(2) 저작권 조건을 어떻게 할지**  ← 매번 묻는다. 기본값으로 넘기지 않는다
> 저작권은 기본값 「인플루언서 업로드 90일 유지 / 저작권 1년 제공」 으로 할까요?

건마다 달라질 수 있는 조건이라 사용자 확인 없이 진행하지 않는다.

## 2. 항상 새로 구성해야 하는 6개 항목

**광고주는 인플루언서 릴스에 무엇을 요청해야 할지 모르는 경우가 많다.**
아래 6개는 광고주가 뭘 적어 냈든 **그대로 내보내지 않는다.** 비었으면 조사해 채우고,
짧으면 보태고, 길면 정리한다.

| 항목 | 비었을 때 | 짧을 때 | 길거나 복잡할 때 |
|---|---|---|---|
| 콘텐츠 방향 (콘텐츠스타일 · 분위기) | `신규` | `추가` | `정리` |
| 반드시 포함되어야 하는 장면 | `신규` | `추가` | `정리` |
| 게시글에 포함해 주세요 | `신규` | `추가` | `정리` |
| 사용하면 안 되는 표현 · 촬영 방식 | `신규` | `추가` | `정리` |
| 브랜드 소개 | `신규` | `추가` | `정리` |
| 필수 해시태그 | `신규` | `신규` | — |

판단 기준:
- **짧다** = 유형 선택 한 줄(`제품, 서비스 집중 소개형`)이거나 한 문장(`오션뷰가 나오는 호텔뷰`).
  인플루언서가 이것만 보고 촬영 장면을 정할 수 없으면 짧은 것이다
- **길다** = 단락이 4개 이상이거나, 같은 말이 반복되거나, 대화체 잔문이 섞여 있다
  (예: "그럼 제외하고 영상에 꼭 필요한 장면만 추리면 이렇게 정리하면 깔끔해.")
- **금지사항이 `없음`** 이어도 그대로 두지 않는다. 인플루언서에게 줄 기준이 없기 때문이다.
  경쟁 브랜드가 보이는 것 / 근거 없이 단정하는 표현 / 다른 손님 얼굴 / 과한 보정 을 공통으로 채운다
- **해시태그는 임의로 만들지 말고 브랜드명·지역·업종에서 끌어낸다.** 확정 아님을 근거에 적는다
- 금지사항에 효능·다이어트 단정 금지가 있으면 **해시태그에서도 그 표현을 빼야 한다**

**조사가 필요하면 WebSearch 를 쓴다.** 업종·위치·메뉴·특징을 확인하지 않고 추측해 채우면 안 된다.

조사·작성 대상이 아닌 항목:

| 항목 | 처리 |
|---|---|
| 일정 · 업로드시점 | 조사 대상이 아니다. `협의` |
| 레퍼런스링크 | 임의로 만들면 안 된다. `별도 전달` |
| 2차활용 | 광고주 답변을 그대로 둔다 (`아직 미정` 포함) |

## 2-1. 어조 — 지시가 아니라 제안으로

**콘텐츠 방향(콘텐츠스타일·분위기)** 과 **게시글에 포함해 주세요** 는 제안형으로 쓴다.
인플루언서의 기획을 막지 않으려는 것이다.

- 첫 줄에 여는 말을 둔다
  - 콘텐츠 방향 → `아래는 참고하시면 좋을 아이디어입니다. 그대로 따르지 않아도 괜찮습니다.`
  - 게시글 → `아래 내용이 자연스럽게 들어가면 좋겠습니다. 문장은 자유롭게 써 주세요.`
- `~해 주세요`, `~해라`, `~로 진행합니다` 대신 `~면 좋겠습니다`, `~면 좋습니다`, `~도 좋습니다`
- 번호 매기기(1. 2. 3.)는 순서를 강제하는 느낌이라 `·` 를 쓴다

**반드시 포함되어야 하는 장면** 과 **사용하면 안 되는 표현·촬영 방식** 은 실제 요구사항이다.
여기는 요청형(`~해 주세요`)을 유지한다. 제안형으로 바꾸면 안 지켜진다.

## 2-2. 용어 — 인플루언서가 읽는 문서다

전문용어를 쓰지 않는다. 광고주 확인용이지만 **최종 독자는 인플루언서다.**

| 쓰지 않는다 | 이렇게 쓴다 |
|---|---|
| IP, 캐릭터 IP | 캐릭터 |
| 후킹, 후킹 요소 | 눈길을 끄는 장면 |
| 톤 / 앵글 / 컷 | 느낌 / 각도 / 장면 |
| 클로즈업 | 가까이서 |
| 지양 / 식별되게 | 피해 주세요 / 알아볼 수 있게 |
| 최상급 표현 | 근거 없이 단정하는 표현 |
| 입지 / 차별점 / 비주얼 | 위치 / 다른 곳과 다른 점 / 보이는 모습 |
| 레퍼런스 | 참고할 만한 콘텐츠 |
| 양산형 | 어디서나 볼 수 있는 비슷한 형태의 |

남겨도 되는 말: 인사이트, 파트너십 광고, 브이로그, 보정, 필터 — 인플루언서가 매일 쓰는 말이다.

**광고주 원문(검정)에 전문용어가 있어도 지우지 않는다.** 원문은 원문이다.
풀어써야 하면 `정리` 로 처리해 **원문과 함께** 쉬운 말을 나란히 보여준다.

## 3. 보완내용.tsv 에 근거까지 남긴다

조사·작성한 내용은 **반드시 기록**한다.
광고주가 준 내용과 포포몬비즈가 만든 내용이 섞이면 나중에 추적이 불가능하다.

```
브랜드 <TAB> 항목 <TAB> 구분(신규|정리|추가) <TAB> 값 <TAB> 근거
```

- 브랜드를 `*` 로 쓰면 **전 캠페인 공통 기본값**. 브랜드 전용 행이 공통보다 우선한다
- 여러 줄 값은 `\n` 으로 구분한다
- `정리` 는 원문이 있어야 적용된다. 원문이 없으면 무시된다
- `추가` 는 원문이 없으면 자동으로 `신규` 로 처리된다
- 근거에는 **무엇을 왜 바꿨는지** 적는다. "포포몬비즈 제안" 만으로는 부족하다
  좋은 예: `원문이 한 줄(오션뷰)뿐이라 객실 소개에 필요한 장면 보완`

TSV 를 만들 때 셸 명령줄로 탭을 넣으려 하지 않는다. 구분자(`||` 등)로 쓴 뒤
perl 로 탭으로 바꾸는 편이 안전하다. 만든 다음 `awk -F'\t' 'NF!=5'` 로 필드 수를 확인한다.

## 4. 공통 기본값 (보완내용.tsv 의 `*` 행)

| 항목 | 값 |
|---|---|
| 영상 길이 | 30초 ~ 1분 내외 |
| 콘텐츠 제출일 | 방문 후 7일 이내 |
| 인사이트 제출 기한 | 콘텐츠 업로드 후 7일 뒤 |
| 업로드 희망 시점 | 협의 |
| 레퍼런스 링크 | 별도 전달 |
| 필수 해시태그 | 별도 전달 ← 브랜드별 제안으로 덮어쓴다 |
| **저작권** | 인플루언서 업로드 90일 유지 / 저작권 1년 제공 ← **매번 사용자 확인** |
| 파트너십 광고 | 제공 필수 |

저작권·파트너십광고는 항목 자체를 빼지 않는다. 폼에 없는 항목이라 `*` 행으로만 들어간다.

## 5. 작성

생성기를 쓴다. 손으로 치환하지 않는다.

```
D='공고/5-1 기획형 인플루언서 공고 가이드'
perl "$D/가이드생성.pl" \
  "공고/5-0 new 기획형 인플루언서 양식폼(응답)/응답/응답시트_19문항.csv" \
  "$D/가이드_양식.html" "$D/_작업" "$D/보완내용.tsv"
```

생성기가 만드는 것:
- `_작업/<브랜드>.html` — 브랜드별 가이드
- `_작업/_목록.txt` — 변환 대상 목록
- `_작업/데이터.json` — 구글 문서·시트로 보낼 데이터 (6번에서 쓴다)
- `_작업/데이터.gs` — 웹앱을 못 쓸 때의 대비용

주의사항:
- **sed 는 쓰지 않는다** (`&` 가 치환 특수문자다). Read/Write/Edit 로 고친다
- **perl 한 줄 명령에 한글 패턴을 쓸 때는 `-Mutf8` 이 필요하다.**
  없으면 소스의 한글이 바이트로 남아 매칭되지 않는다. 조용히 아무 일도 안 일어난다
- 양식 맨 위 주석 블록은 결과 파일에서 삭제된다
- `_작업/` 은 한 단계 아래이므로 이미지 경로가 `../이미지/` 로 바뀐다
- **기본 제작 안내와 상단 범례는 `가이드_양식.html` 이 유일한 기준이다.**
  생성기가 양식에서 뽑아 데이터로 넘기므로, 고쳐도 `.gs` 를 만지거나 재배포할 필요가 없다
- 표 헤더는 `th { width:130pt; white-space:nowrap }` 로 고정돼 있다. 손대면 워드에서 세로쓰기가 된다
- 긴 URL 은 생성기가 폭 없는 공백을 넣어 줄바꿈시킨다. 보이는 글자는 바뀌지 않는다

## 6. 저장 — 파일 + 구글 문서 + 시트를 **항상 같이** 한다

세 곳이 어긋나면 광고주에게 다른 내용이 두 번 전달된다. 하나만 하고 끝내지 않는다.

**(1) DOCX · PDF**
```
while IFS= read -r n; do
  bash 도구/문서변환.sh "$D/_작업/$n.html" "$D/발행" "$n 콘텐츠 제작 가이드"
done < "$D/_작업/_목록.txt"
```
가이드는 여러 장이 정상이므로 페이지 수는 문제가 아니다.
`미리보기.sh` 는 한 장짜리 견적서용이라 여기서는 쓰지 않는다.

**(2) 구글 문서 + 관리 시트 — 이것도 내가 한다. 사용자에게 미루지 않는다**
```
bash "도구/시트올리기.sh" "$D/_작업/데이터.json"
```
Apps Script 웹앱으로 데이터를 보내면 사장님 계정 권한으로 브랜드별 구글 문서와
`0_가이드 관리` 시트가 갱신된다. 결과에 문서 링크가 돌아오므로 보고에 그대로 쓴다.

- 기존 문서를 건너뛰려면 `bash "도구/시트올리기.sh" "<json>" 유지`. **기본은 덮어쓰기**다
- `연동/.env` 가 없거나 비어 있으면 스크립트가 무엇을 해야 하는지 알려준다.
  그때는 세팅 절차를 안내하고, **다 될 때까지 "완료" 라고 하지 않는다**
- HTML 이 돌아오면 배포 접근 권한이 `모든 사용자` 가 아닌 것이다
- **`.gs` 를 고쳤을 때만 재배포가 필요하다.** 내용·문구 수정은 재배포 없이 반영된다.
  재배포는 「배포 관리 → 편집 → 새 버전」 이다. 「새 배포」 를 쓰면 URL 이 바뀌어 `.env` 도 고쳐야 한다
- 브랜드가 15건을 넘으면 Apps Script 6분 제한에 걸린다. 나눠 보낸다
- **웹앱 URL·비밀키를 대화에 출력하지 않는다.** 사실상 암호다

**(3) 미리보기 PNG** — 보고용. 크롬 인스턴스가 겹치면 실패하므로 `--user-data-dir` 를 다르게 준다

## 7. 저장 직전 자기검증

- [ ] 남아 있는 `{{변수}}` 가 0개인가
- [ ] `작성 필요` 로 남은 항목이 0개인가
- [ ] **저작권 조건을 사용자에게 확인받았는가**
- [ ] 2절의 6개 항목이 전부 처리됐는가 (원문 그대로 나간 항목이 없는가)
- [ ] **금지사항이 `없음` 인 채로 나가지 않는가**
- [ ] **콘텐츠 방향·게시글 보완이 제안형인가** (지시형이면 다시 쓴다)
- [ ] **내가 쓴 빨간 글씨에 전문용어가 없는가** (검정 원문은 그대로 둔다)
- [ ] 태그가 **이 브랜드의** 계정인가 (다른 브랜드 계정을 태그하면 사고다)
- [ ] 해시태그가 금지사항과 충돌하지 않는가 (효능·다이어트 단정 등)
- [ ] 정리·보완한 항목에 **원문이 함께** 표시되는가
- [ ] 조사·작성 내용이 `보완내용.tsv` 에 근거와 함께 기록됐는가
- [ ] DOCX 표 폭이 본문폭(9026 twip)을 넘지 않는가
- [ ] `데이터.json` 이 새로 만들어졌는가
- [ ] **`시트올리기.sh` 를 돌려 구글 문서·시트까지 갱신했는가** (로컬 파일만 만들고 끝내면 안 된다)
- [ ] 이전 브랜드의 정보가 남아 있지 않은가

어긋나면 저장하지 말고 수정 후 재검증한다.

## 8. 보고

- DOCX·PDF 경로와 **구글 문서·관리 시트 링크**를 함께 알려준다
- 1페이지를 PNG 로 만들어 이미지 링크로 보여준다
- **무엇을 조사·작성·정리했는지 항목별로 밝힌다.** 광고주 확인용 문서라 이게 핵심이다
- 광고주 원문에 손대지 않고 남긴 부분이 있으면 그것도 밝힌다
- 광고주 담당자 연락처는 대화에 출력하지 않는다

## 9. 금지사항

- 브랜드 정보·필수 장면·태그 계정을 **조사 없이** 추측해 채우기
- **광고주 원문을 지우고 내 글로 갈아치우기** (정리·보완할 때는 원문을 반드시 남긴다)
- **저작권 조건을 묻지 않고 기본값으로 진행**
- 금지사항을 `없음` 그대로 내보내기
- 콘텐츠 방향·게시글을 지시형으로 쓰기
- 전문용어를 내 글(빨강)에 쓰기
- 상단 범례·기본 제작 안내를 `.gs` 쪽에서 고치기 (양식이 기준이다)
- 파일만 만들고 구글 문서·시트를 안 올리기
- 검증 실패 상태로 "완료" 보고
- 요청하지 않은 git commit / push
