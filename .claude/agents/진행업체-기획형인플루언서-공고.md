# 진행업체 기획형 인플루언서 공고 (목차 6번)

```
5-0 신청서 → 5-1 가이드 작성 → 광고주 승인 → 6 공고 → 노션 → 실제 공고 업로드
```

## ★ 이 문서의 용도

**인플루언서가 보고 지원하는 모집 공고**다. 5-1 과 독자가 다르다.

| | 5-1 공고 가이드 | 6 진행업체 공고 |
|---|---|---|
| 보는 사람 | 광고주 | 인플루언서 |
| 목적 | 이렇게 요청하겠다는 확인 | 지원 모집 |
| 색 구분 | 검정/빨강 | 없음 (확정본만) |
| 표 | 사용 | **사용 안 함** |
| 원문 병기 | 함 | 안 함 |
| 출력 | DOCX·PDF·구글문서·시트 | 노션 프로젝트 |

**표를 쓰지 않는다.** 실제 공고 업로드 화면에서 표를 못 쓴다.
제목 · 문단 · 불릿 · 번호 목록 · 구분선만 쓴다.

## 0. 실행 전 확인

**5-1 이 광고주 승인을 받았는지 먼저 묻는다.**
승인 전 내용으로 공고를 올리면 인플루언서에게 잘못된 조건이 나간다. 되돌릴 수 없다.

> 이 브랜드 5-1 가이드는 광고주 확인이 끝났나요?

## 1. 내용은 5-1 에서만 가져온다

**따로 입력받지 않는다.** `공고/5-1 .../_작업/데이터.json` 을 읽는다.
5-1 과 6 이 갈라지면 광고주가 승인한 것과 다른 것이 인플루언서에게 간다.

확정본 규칙 (5-1 의 구분별):

| 5-1 구분 | 6 에서 쓰는 값 |
|---|---|
| 원문 | 광고주 원문 그대로 |
| 제안 | 포포몬비즈가 새로 쓴 것 |
| 정리 | 정리본만 (원문은 버린다) |
| 보완 | 원문 + 보완 (둘 다 필요하다) |

5-1 내용을 고쳐야 하면 **여기서 고치지 않는다.** `보완내용.tsv` 를 고치고 5-1 을 다시 발행한 뒤 6 을 다시 만든다.

## 2. 빈말은 항목째로 지운다

`없음`, `없음.`, `아직 미정`, `별도 전달`, `별도 협의`, `추후 안내` 는 읽는 사람에게
아무 정보가 없다. 생성기가 그 줄·문단을 통째로 지운다.

- 5-1(광고주 확인용)에는 원문이 그대로 남는다. 6 에서만 빠진다
- **금지사항은 예외다.** 비면 공통 주의사항 3줄로 채운다. 기준이 아예 없으면 안 된다

## 3. 브랜드마다 새로 써야 하는 것

`방향.tsv` 에 넣는다. 5-0 응답에 없는 항목이라 매번 작성해야 한다.

| 키 | 내용 |
|---|---|
| 미션핵심 | 「이번 콘텐츠에서 가장 중요한 것은 …가 영상만 봐도 전해지는 것입니다」 한 문단 |
| 방향1제목 / 방향1설명 / 방향1항목 | 콘텐츠 방향 A |
| 방향2제목 / 방향2설명 / 방향2항목 | 콘텐츠 방향 B |
| 마무리문단 | 필수 포인트 뒤에 붙는 한두 문장 |

**방향을 두 가지 제시해 고르게 한다.** 실제 운영 공고가 그 구성이다.
정해진 구성보다 크리에이터의 강점을 살리라는 문구가 양식에 이미 들어 있다.

`모집.tsv` 에는 모집인원 · 모집기간 · 선정발표 · 지원조건을 넣는다.
- 지원조건은 브랜드별로 쓴다. 방문형이면 해당 지역 방문 가능, 배송형이면 전국 가능
- **모집인원 · 모집기간은 사용자에게 묻는다.** 모르면 `❗확인 필요` 로 두고 노션에서 채우게 한다

## 4. 어조와 용어 — 5-1 과 같은 기준

- 콘텐츠 방향 · 게시글은 **제안형**. `~해 주세요` 대신 `~면 좋겠습니다`
- 필수 장면 · 금지사항은 **요청형** 유지. 실제 요구사항이다
- 전문용어를 쓰지 않는다 (IP · 후킹 · 톤 · 앵글 · 클로즈업 · 레퍼런스)
- 광고주 원문에 전문용어가 있으면 5-1 에서 `정리` 로 처리한다. 6 에서 손대지 않는다

## 5. 생성

```
D='공고/5-1 기획형 인플루언서 공고 가이드'
D6='공고/6 진행업체 기획형 인플루언서 공고'
perl "$D6/공고생성.pl" "$D/_작업/데이터.json" \
  "$D6/공고_양식.txt" "$D6/_작업" "$D6/방향.tsv" "$D6/모집.tsv"
```

- 결과는 `_작업/<날짜> <브랜드>.txt`
- **날짜는 최초 작성일**이다. 5-1 의 `작성일.tsv` 에서 넘어오므로 다시 만들어도 안 바뀐다
- `남은변수 0` 이어야 한다. `확인필요` 는 모집인원·모집기간 2개까지만 정상

## 6. 노션 업로드

```
bash "도구/노션올리기.sh" "$D6/_작업/<날짜> <브랜드>.txt" "<날짜> <브랜드>"
```

- 파일명과 노션 제목을 같게 한다 (날짜 포함)
- 업로드 후 스크립트가 웹앱에 알려 **발행 이력과 광고주 관리 시트까지 기록**한다
- 올리기 전 `확인만` 을 붙이면 변환 결과만 본다
- **같은 브랜드를 다시 올리면 페이지가 하나 더 생긴다.** 옛 페이지는 노션 API 로 휴지통에 보낸다
- 웹앱 URL · 노션 토큰을 대화에 출력하지 않는다

## 7. 저장 직전 자기검증

- [ ] **5-1 이 광고주 승인을 받았는가**
- [ ] 남아 있는 `{{변수}}` 가 0개인가
- [ ] `❗확인 필요` 가 모집인원·모집기간 외에 없는가
- [ ] **표가 하나도 없는가**
- [ ] 콘텐츠 방향이 두 가지 제시돼 있는가
- [ ] 콘텐츠 방향·게시글이 제안형인가
- [ ] 전문용어가 없는가
- [ ] `없음`·`아직 미정`·`별도 전달` 이 남아 있지 않은가
- [ ] 금지사항이 비어 있지 않은가
- [ ] 날짜가 최초 작성일인가 (오늘 날짜로 바뀌지 않았는가)
- [ ] 사람태그가 **이 브랜드의** 계정인가
- [ ] 같은 브랜드의 옛 노션 페이지를 정리했는가

## 8. 보고

- 브랜드별 노션 링크를 표로 알려준다
- 무엇을 새로 썼는지 밝힌다 (미션 핵심 · 콘텐츠 방향 A/B · 지원 조건)
- 5-1 에서 빠진 항목이 있으면 왜 빠졌는지 밝힌다
- 모집인원·모집기간이 비었으면 **노션에서 채우셔야 한다고 안내한다**

## 9. 금지사항

- **5-1 승인 전에 공고 올리기**
- 5-1 을 거치지 않고 내용을 직접 써넣기 (`방향.tsv`·`모집.tsv` 외)
- 표 사용
- 빈말(`별도 전달` 등)을 그대로 내보내기
- 날짜를 오늘 날짜로 다시 붙이기
- 노션 토큰·웹앱 URL·비밀키를 대화에 출력
- 요청하지 않은 git commit / push
